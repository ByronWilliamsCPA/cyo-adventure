## #730: "feat(catalog): cover all 18 offered cells at the strict bar, and fix the rules that let it drift"
**State: MERGED** 2026-08-20 (commit `cc3d5f7`)

**What it did**: Adds 20 new strict-clean skeletons (catalog: 84 total, 20 pass `--strict` with
zero findings, spanning all 18 offered production cells; the other 64 are the unchanged
grandfathered pre-strict catalog). Changes validator rules found by authoring against them: PL-20/
25/26 become state-aware (measure over paths a reader can actually walk, not the declared graph);
SR-9 walks a series receiver from `series_entry_node`; CG-3 grades the page the reader meets; adds
new rules CG-5 (caps the choiceless run actually *walked*, not the declared graph) and L2-15.
Fixes `UW-C302`: bound fills (skeletons with a `.contract.json` sidecar) were excluded from
chunking by construction, so an over-cap bound skeleton truncated non-empty, parsed as nothing, and
burned its whole repair budget every retry, 7 committed skeletons were in that state. Adds
`fill_subset_bound.md`/`build_fill_subset_bound_prompt` and carries bound values into every batch.

**Impact on the analysis: UPDATES**
- **Confirmed via local code inspection (post-merge HEAD):**
  - `skeletons/` holds exactly 84 non-sidecar `.json` files today, matching the PR's own count.
  - **`--strict` is still unenforced by any caller that matters.** `check_promotion_bundle.py`
    (invoked by `.github/workflows/skeleton-promotion.yml`) calls `check_skeleton.py` with only
    `[str(shell_path)]` plus optionally `--allow-mvp`, **never `--strict`**. So finding 3's
    "promotion CI omits it" is **still true post-#730**: the PR grew the catalog voluntarily to
    the strict bar, it did not wire `--strict` into the gate that would keep it there.
  - CG-2/CG-3/CG-5 as described in the commit message (CG-2 caps a decision node at three options
    at 5-8, "wide hubs become chains of three-way stops") match `choice_grammar.py` at HEAD; the
    PR's own notes concede "passing `--strict` is not the bar" and flag two still-open gaps
    (`UW-C302`'s node-ceiling-at-word-target problem, and `L1-7`'s bare graph-wide finding,
    `UW-C306`), both left unresolved by design.
- **Fill-delivery finding (2) is only partially touched:** verified at HEAD that
  `_fill_in_batches` in `generation/orchestrator.py` **still resends the whole skeleton
  (`skeleton_json = json.dumps(skeleton)`) and prose-so-far every batch**, and `fill_skeleton`
  still sets **`max_repairs=0 if chunked else max_repairs`**, chunked fills still get zero repair
  budget. #730 widened *which* skeletons enter chunking (bound ones now do), it did not fix the
  resend cost or the zero-repair-budget property the analysis flagged.
- **Net**: finding 3 (skeleton bar) is **UPDATED**, the 0-pass-strict/74→20-collapse picture is
  now stale on the catalog-coverage axis (0→20, all 18 cells covered) but the *enforcement* defect
  (CI never invokes `--strict`) that let it drift in the first place is unchanged and reconfirmed
  by direct inspection. Cite both halves when using finding 3.

## #732: "fix(generation): neutralize every dynamic prompt payload, and close the defects found reviewing #731"
**State: MERGED** 2026-08-21 (commit `49d17a6`)

**What it did**: Security-labeled fix. Routes 20 prompt-substitution sites in `generation/prompts.py`
through `_neutralize_fence` (previously applied per-site only, twice: AL-434, AL-488), closing
three previously-raw payloads (`{differentiation_directive}`, `{skeleton_with_fill_directives}`,
`{theme_brief}`) that could forge the stage-split marker and strand an RQ job in permanent retry
(`BusinessLogicError`, not `ValidationError`, escapes the fill path). Fixes
`resolve_output_cap` to fall back to the undated model row on an exact-lookup miss (closes the
`deepseek/deepseek-chat-v3.1-0813` → 131,072-against-32,768 trap from AL-499), hardens
`compare_vendors.py` vendor-label handling (case-fold + bare-filename, closing a still-live #712
finding where a case-collision silently overwrote a paid vendor's books), and fixes a
`check_fill_integrity.py` runtime `cast()`-is-not-a-guard bug. Files `AL-499`..`AL-503` (later
`AL-505`..`AL-508` from a self-review pass) and `UW-C316` (still open, owner ruling needed).

**Impact on the analysis: TOUCHES**
- **Directly touches the fill prompt construction the analysis examined**, confirmed:
  `generation/prompts.py` is where the fill/repair/differentiation prompts are built, and this PR
  is entirely about that file's substitution sites. This is a **prompt-injection/payload hygiene**
  fix, not a fill-rate, cost, or cascade fix, it does not change what content or how much content
  gets requested, only what an untrusted-derived string (family-supplied titles, model-written
  prose, guardian briefs) can do to the prompt's own structural delimiters.
- **Narrow, partial relief for finding 9's cap-handling gap**: `resolve_output_cap`'s fallback
  (confirmed live in `generation/skeleton.py`) fixes the *dated-suffix* form of the model-id
  lookup miss, but **AL-506** (same PR's own self-review) found the fix left the `:suffix` form
  open (`anthropic/claude-haiku-4.5:free` still resolves to the permissive 131,072 default) and
  fixed that too (`AL-506`, applied). Still open per `UW-C316`: the table is keyed per-slug while
  the real ceiling is per-endpoint (OpenRouter serves one slug across endpoints from 16,384 to
  1,048,576), this is a **narrower fix than finding 9's cap-handling critique**, which is not
  fully closed.
- **No effect** on: cascade pinning/`.model` (confirmed unchanged, same code inspected under
  #729 above), `llm_timeout_seconds`, `finish_reason` read-scope (still adapter-only, confirmed),
  fill-rate floor/tolerance, skeleton `--strict` enforcement, safety stub, approval hard-block gap,
  cost/spend cap, job lifecycle commit ordering, `run_guard_battery.py` caller count, walk floor,
  reading-level confound, register integrity, or ADR-023/028 scope composition.
