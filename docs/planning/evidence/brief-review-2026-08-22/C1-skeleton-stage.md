1. [CRITICAL] [4.2, F3] The S-1 conclusion is a pass-rate conclusion, and the programme's own lessons say strict passes do not measure skeleton quality.
F3 calls the regime "the single largest quality lever we have measured"; the only endpoint in the tool condition is strict pass/fail plus checker invocations. The programme already knows this bar is hollow: AL-147 (open): "Strict-clean does not mean approvable... three drafts in three different cells each passed check_skeleton --strict with zero findings"; AL-148: outcome gates read tags, not outcomes; AL-149 (open, UW-C86): choice fairness and consequence are "invisible to every current metric" (77% position bias, 25 decision nodes with byte-identical reachable-ending sets). The fill stage got a delivery floor after AL-490; the skeleton analogue, the shell rubric (plan section 4 Tier 3: beat coherence, "whether decision points are meaningfully different choices", ending differentiation), is still "to build"; no rubric artifact exists in any run dir. S-3 measures premise fit of finished books, not shell craft. The model designated to author every armature was selected with zero above-floor quality evidence, exactly the F2 mistake the brief warns against one section earlier.
Recommendation: run the shell rubric blind over the 26 tool-passed shells vs 5-8 catalog shells; add AL-149 consequence checks to the strict bar; state in 4.2 that the table measures convergence-to-floor, not skeleton quality.

2. [CRITICAL] [4.2, F4] The tool condition compares three different harnesses, has no reproducible implementation, and its cap is not the same cap across legs.
compare_skeleton_authors.py implements only the blind loop plus --emit-prompts/--score-shell; the tool condition ran through an unversioned external driver. e1r3-tools has no run.json; every record shows attempts: 1, tokens: null, latency: 0, finish_reasons: [] even for 10-checker-run points, so checker-run counts trace only to hand-maintained tools-meta.json, which is missing all six cell-D DeepSeek entries. Transport differs per family: Anthropic legs are in-session subagents with native tool use, repo access, and unlimited turns between 10 checker invocations; kimi/DeepSeek legs got a manual text-JSON loop where the 10 calls double as the only checker chances (flash A r1 died at 2 checker runs after 8 unparseable calls). The same flash completed six-round blind loops through the scripted harness the same day (282,624 output tokens, one strict pass), so "call budget lost to unparseable output" is at least as attributable to the driver's parsing path as to the model; no transcript survives to adjudicate. Within-harness claims (tool beats blind; Anthropic frontier converges fastest among subagents) stand; cross-lab rankings, incl. F4's "worst structure author measured (0 of 6)", do not.
Recommendation: implement the tool loop in the harness (structured-output mode for API legs, checker runs as the counted unit for all), persist transcripts and usage, re-run the DeepSeek cells before F4 ships as a principle.

3. [HIGH] [4.2, F7, 4.5] The adopted authoring regime has no measured cost; the brief never connects catalog demand to skeleton-side economics.
No token, dollar, or wall-clock figure exists for any tool-assisted shell (tool records null usage; blind kimi records also output_tokens null; no Modal billing figure anywhere); 4.5 covers only fill-stage comparison spend. F7's "Haiku... at zero marginal cost" is subscription-plan accounting, and Haiku's overall tool pass rate was 3/6. Demand side is quantified elsewhere: Q-1 (exhaustion by ~4th request at 3-4 skeletons/cell), 18 production cells (band_profile._PRODUCTION_CELLS), S-5's amortization basis (2 review-hours/skeleton, 50 books/skeleton). Doubling depth is ~61 shells, ~122 review hours plus 2-10 checker-run sessions each; the brief prices none of it.
Recommendation: instrument production cyo-author sessions for tokens per accepted shell; add "cost per accepted skeleton (authoring + review)" to 4.5; let S-5's amortized comparison consume it.

4. [HIGH] [3.2] The anti-clone bullet misdescribes enforcement: TAU_CELL is not in check_skeleton --strict, and promotion skips it for exactly the shells the new regime produces.
check_skeleton.py contains no structural_distance or TAU_CELL reference (grep: zero hits); the S-1 harness computed catalog distance as exploratory only. check_promotion_bundle.py applies the floor only to shape-changed mutants; for originals it logs "parent-hash and anti-clone floor not applicable" (~line 354). AL-151 recorded this disjunction ("a strict-passing draft can be inadmissible three separate ways and nobody sees it until commit"), open as UW-C88. Only enforcement for a hand-authored original is the whole-catalog audit check_incell_clones.py --check in ci.yml (line 580), which fires after the file is in the tree. Matters now because tool-authored passes land close to the floor (finding 7).
Recommendation: correct 3.2; add the in-cell TAU_CELL check to check_skeleton --strict (cell mode knows the cell) so the authoring loop sees it.

5. [HIGH] [3.1] The "complete constraint set" claim is false: the brief generator omits PL-25 and PL-18 shape semantics, and S-1 legs were scored against the unstated rules.
build_brief has no entry for PL-25 (first-decision window), which sits in STRICT_BLOCKING_WARNINGS (check_skeleton.py ~line 103); nothing states what makes a graph shape admissible for a declared topology (PL-18): the topology block covers only the PL-29 allowed list and in-degree caps, so the tree-uniqueness rule that trapped sonnet twice is unstated. DeepSeek pro's A r2/r3 final feedback includes PL-25, so its 0/6 partly rests on a constraint the brief never gave it, violating the plan's own control ("a failure against an unstated constraint indicts the brief... not scored against the arm", section 7). Drift protection is one-sided: test_generate_drafting_brief.py asserts published values equal enforced sources (good, post AL-476) but no completeness test (every strict-escalated rule id has a brief entry). None of the 11 PL-25 mentions in the UW register tracks this omission.
Recommendation: add PL-25 and a PL-18 shape-semantics block to build_brief, plus a completeness test over STRICT_BLOCKING_WARNINGS.

7. [MEDIUM] [3.2, 4.2] Checker-in-the-loop Goodharting is undiscussed; passing shells sit far closer to the catalog than hand-authored work sits to itself.
All 26 tool-condition passes have min catalog structural_distance 0.051-0.239; opus A r3 passed at 0.0507, 0.0007 above TAU_CELL (0.05); 8 of 26 sit below the hand-authored same-cell 5th percentile (0.155, ws5_floor_baseline.json, n=145 pairs; p25 0.298, median 0.380). Nothing treats near-floor clearance differently, and (finding 4) the floor was not even part of the bar being iterated against, so this proximity is uncoerced convergence toward existing catalog shapes. Subagent legs could additionally read check_skeleton.py thresholds and the in-cell catalog inside the repo, an affordance API legs lacked; no transcripts exist to verify they did not. Quality-per-dollar collapses if cheap passes are near-clones the reader has effectively already met.
Recommendation: report floor-margin distributions per leg in 4.2; pre-register a margin-above-floor secondary for the next authoring run.

8. [MEDIUM] [3.1] The offline accelerators are presented as live supply while the evidence base undercuts both; the acceptance battery cannot see the defect that matters.
S8/P1: shape-preserving mutants sit at structural_distance 0.0000 from parent, "no bounded single-parent mutant cleared TAU_CELL", every mutant kept 100% of parent beats, "the beats are the fingerprint". The D7 acceptance leg is TAU_CELL against parent plus siblings, so the battery rejects shape-preserving mutants by construction; the only floor-clearing acceptance ever grafted 32 nodes from a second skeleton (Q-2 recombination), which the register blocks on contract coverage (2 of 61, AL-213). The battery's checks (gate, budgets, TAU_CELL, reguide resolution, mock sample-fill) contain no perceptual or beat-level distinctness measure; recognition failed S-0. parameterize_skeleton.py byte-preserves roles/words and fingerprints, so theme contracts multiply bindings over identical beat sets: per P1 and AL-498 that buys cross-reader capacity, never per-reader variety; D-6 makes sharing the contract itself a convergence cause. 3.1 flags neither scope limit.
Recommendation: one sentence per tool in 3.1 stating what each cannot supply (per-reader variety) until S-4 says otherwise.

10. [MEDIUM] [3.1] Promotion: the human-merge-only guard is label-gated with nothing forcing the label; reviewer duties/capacity appear nowhere.
skeleton-promotion.yml is strong on re-proving (fail-closed diff, check_promotion_bundle.py on every changed shell, derived-artifact currency, auto-merge guard re-armed on toggle events). But the no-auto-merge job runs only if labels contain 'skeleton-promotion', and no automation applies that label: a PR touching skeletons/** without it can enable auto-merge and land on green checks with no human reading the shell (the ADR-020 decision-4 boundary; branch-protection could close it but is unverifiable from the tree). Neither 3.1 nor any companion defines what the reviewer checks beyond the gate (beat quality, choice meaningfulness, the AL-147 approvability gap); the 2 review-hours/skeleton S-5 prices never enters the brief's cost story.
Recommendation: lightweight labeler (or make the guard unconditional on the path filter); write the reviewer checklist the shell rubric will eventually automate.

Strengths

- The 4.2 table is honest to its records: every printed pass count, checker-run range, and the blind 2/21 recompute exactly; the tool-vs-blind contrast is a large, robust effect no harness asymmetry plausibly erases.
- The brief-generator loop (AL-149/AL-476 lineage, per-cell equality tests, live reads of enforced sources) is a genuinely good pattern; gaps found are omissions from it, not failures of it.

Top 3
1. The skeleton stage has no above-floor quality measure at all, so F3/4.2 select the structure author on gate passes the programme's own open lessons (AL-147/148/149) say do not indicate an approvable, meaningfully-branching shell.

3. Skeleton unit economics are unquantified end to end while Q-1's demand math makes catalog growth a near-term recurring cost.
